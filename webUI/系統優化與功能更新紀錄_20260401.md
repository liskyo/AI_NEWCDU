# 🚀 Guchii CDU Control 系統優化與功能更新紀錄

**更新日期：2026-04-01**

本文件彙整了近期針對「Guchii CDU 控制系統」所進行的核心效能優化、展示引擎開發以及系統穩定性提升之完整紀錄。

---

## 1. 展示模式引擎 (DEMO MODE Engine) - 全面升級
為了解決展示開發與現場演示時「無實體 PLC 硬體」的限制，我們在後端構建了強大的動態模擬引擎。

*   **[優化] 數據平滑化模擬**：捨棄前端 local 亂數，改由後端透過 `math.sin` 演算法模擬具備真實波動感的溫度、壓力與流量數據，並同步推播至全系統 (Status, Control, Trends)。
*   **[修復] 504 Gateway Timeout 徹底解決**：針對多個核心 API 路由（如 `/get_data_control`, `/read_version`）實作了 **Bypass 攔截機制**。當 `TEST MODE` 開啟時，系統會立即回傳記憶體數據，不再等待無響應的 Modbus 連線，確保展示過程毫無延遲。
*   **[新增] 動態警報仿真系統**：
    *   實作「隨機異常注入」機制，每 15 秒會隨機觸發一項系統警告（如：漏水、水溫過高、幫浦異常）。
    *   自動化「警報恢復 (Restore)」模擬，確保 Logs 分頁具備生動的發生與解除紀錄。
    *   退出測試模式時，系統具備「自動清空假警報」之清理機制，不干擾正規日誌。

## 2. 前端 UI/UX 與 全域同步化
提升了跨頁面操作的一致性與專業技術美感。

*   **[優化] 全域 TEST MODE 切換**：重新設計所有分頁（Status, Control, Trends, Logs）的 Test Mode 開關，確保不論從哪個分頁切換，全系統的數據源與 UI 狀態皆能即時同步，不再出現分頁狀態不一的情況。
*   **[優化] 響應式趨勢圖系統**：微調 `Trends.vue` 的資料獲取路徑，將其與後端 `/api/status` 統一，讓圖表能精準繪製出後端產生的模擬波形。
*   **[新增] 專屬戰情室 (Kiosk Mode)**：優化了全螢幕自動輪播功能，讓系統能在「狀態總覽」與「趨勢分析」間智能切換，適合用於展示廳大型螢幕。

## 3. 多國語系與在地化 (Localization)
針對繁體中文市場進行了深度客製化。

*   **[新增] 輕量化 i18n 語系切換**：在導航列實作了無延遲的中英雙語切換功能。
*   **[優化] 專業術語翻譯**：屏除生硬的機器翻譯，改採工業控制領域之專業用語（例如：`狀態總覽`、`設備控制`、`趨勢分析`、`維護保養`、`工程模式` 等），提升產品成熟度。

## 4. 系統穩定性與通訊埠優化 (今日更新)
因應 Windows 環境的通訊限制進行了關鍵修復。

*   **[修復] 徹底解決通訊端被拒絕 (Access Denied) 錯誤**：
    *   **問題診斷**：確認 Windows (WinNAT/Hyper-V) 將原本的 `5501` 埠號歸類為排除範圍 (Excluded Port Range)，導致 Flask 啟動失敗。
    *   **解法實作**：全面將系統後端連線、Vite Proxy 代理以及全域 Axios 配置遷移至安全的 **`5588`** 通訊埠，避開系統保留範圍，確保在任何 Windows 環境下都能穩定開啟。

## 🌟 維護小提示
*   若未來再次遇到啟動失敗 (Permission Denied)，可執行 `netsh interface ipv4 show excludedportrange protocol=tcp` 檢查目前 Windows 的保留範圍。
*   目前的 `5588` 埠號為自訂的安全範圍，建議保持此設定。
